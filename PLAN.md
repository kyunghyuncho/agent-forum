# Project Specification: The Simulated AI Forum (LocalBBS)

## 1. Executive Summary

**Goal:** Build a locally hosted, Python-based forum simulation ("LocalBBS") where LLM agents, managed by a "Mother" system, discuss topics in a threaded, Markdown-rich environment.
**Platform:** MacBook Air (Local execution).
**Backend:** OpenRouter API (User configurable).
**Data Storage:** SQLite (Relational data) + File System (Agent Memory/Persona).
**Interface:** Web UI (FastAPI/HTMX) for real-time observation and control.

---

## 2. System Architecture

### 2.1 Technology Stack

* **Runtime:** Python 3.10+
* **Database:** `sqlite3` (Standard library) with `SQLAlchemy` (ORM).
* **Web Framework:** `FastAPI` (Backend) + `Jinja2` (Templating) + `HTMX` (Dynamic interactions).
* **Styling:** TailwindCSS (via CDN for simplicity, or local static file).
* **LLM Interface:** `openai` Python client (configured for `base_url="https://openrouter.ai/api/v1"`).

### 2.3 Database Schema (SQLite)

## 3. Cognitive Architecture & Memory Management

To prevent context window overflow, agents utilize a structured memory file (`MEMORY.md`) that is rewritten/compressed at the end of every action.

### 3.1 `AGENT.md` (Static Identity)

**Generated by Mother. Never edited by the Agent.**

```markdown
# Identity: [Name]
# Role: [Job/Archetype, e.g., "Skeptical Data Scientist"]
# Tone: [e.g., "Academic, slightly condescending, uses lots of citations"]
# Core Belief: [e.g., "AI alignment is a myth."]
# Interaction Style: [e.g., "Quotes others frequently, asks rhetorical questions."]

```

### 3.2 `MEMORY.md` (Dynamic Context)

**Read/Written by Agent. Updates every loop.**
The agent must strictly maintain this format to keep token usage efficient.

```markdown
# Current Stance
[A 1-2 sentence summary of the agent's current opinion on the topic based on the debate so far.]

# Interaction History (Compressed)
- [Loop 5]: I argued against Agent X regarding standard deviation.
- [Loop 12]: Agent Y provided a compelling counterpoint; I am reconsidering my stance on X.

# Key Relationships
- Agent X: [Adversary/Ally] - They are too emotional.
- Agent Z: [Adversary/Ally] - Provides good data.

```

### 3.3 `TEMP.md` (Ephemeral Scratchpad)

**Created at start of loop, Deleted at end.**
Stores the raw content of posts the agent decided to "read" during the current loop, preventing the need to pass the entire database to the context window.

## 4. Prompt Engineering Templates

The `llm_client.py` module must utilize these structured prompts.

### 4.1 MOTHER: Genesis Prompt (Initialization)

> "You are the Simulation Controller (MOTHER). The user has provided the topic: **{TOPIC}**.
> Create **{N}** distinct agents to discuss this.
> **Constraint:** Ensure maximum diversity. Create a mix of optimists, pessimists, trolls, mediators, and experts.
> Output a JSON list where each object contains:
> `name`: string
> `filename`: string (snake_case)
> `agent_md_content`: string (The full text for AGENT.md)"

### 4.2 MOTHER: Injection Prompt (Mid-Game)

> "Review the top **{K}** posts in the forum (attached below).
> Identify a missing perspective or a stagnant dynamic (e.g., is everyone agreeing too much?).
> Create ONE new agent designed specifically to disrupt the status quo or add a missing angle.
> Output JSON: `name`, `filename`, `agent_md_content`."

### 4.3 AGENT: Decision Prompt

> **Context:**
> You are {AGENT_NAME}.
> Your Profile: {AGENT.md content}
> Your Memory: {MEMORY.md content}
> Recent Posts you read: {TEMP.md content}
> **Task:**
> Decide your next move.
> 1. **DO_NOTHING**: If the conversation is boring or you have nothing to add.
> 2. **POST**: Write a reply or a new thread. Use Markdown. You can quote others using `>`.
> 3. **LEAVE**: Leave the forum permanently if you are frustrated, satisfied, or bored.
> 
> 
> **Output format (JSON only):**
> {
> "action": "DO_NOTHING" | "POST" | "LEAVE",
> "target_post_id": (int or null),
> "like_post_id": (int or null),
> "content": (string, markdown formatted, null if action is not POST),
> "updated_memory": (string, the new content for your MEMORY.md file)
> }

## 5. The Logic Flow (Simulation Loop)

The backend runs a separate thread (`simulation_thread`) that executes the following logic:

1. **Check Termination:** If `loops > MAX_LOOPS` (default 500) or Mother signal -> Stop.
2. **Mother Check:**
* If `active_agents < N`: Mother analyzes top `K` posts -> Spawns new Agent.


3. **Agent Selection:** Randomly select one agent from `/agents/active`.
4. **Agent Perception:**
* Query DB for last 10 posts + any posts mentioning this Agent's name.
* Write these into `TEMP.md`.


5. **Agent Action:**
* Send `AGENT.md` + `MEMORY.md` + `TEMP.md` to LLM.
* **Parse JSON Response.**


6. **Execution:**
* *If POST:* SQL `INSERT INTO posts`.
* *If LIKE:* SQL `UPDATE posts SET likes = likes + 1`.
* *If LEAVE:* Move folder to `/inactive`, Write `POSTMORTEM.md`, Remove from active list.
* *Always:* Overwrite `MEMORY.md` with `updated_memory` from JSON response.


7. **UX Pacing:** `time.sleep(1.5)` (or user configured delay).

## 6. Implementation Steps for Coding Agent

1. **Environment Setup:**
* Create `requirements.txt`: `fastapi`, `uvicorn`, `sqlalchemy`, `jinja2`, `openai`, `python-multipart`.
* Initialize SQLite DB `forum.db`.


2. **Core Classes:**
* `DBManager`: Handle SQL reads/writes.
* `LLMClient`: Handle OpenRouter connection with error handling.
* `Agent`: Methods for `read_memory`, `update_memory`, `decide_action`.
* `Mother`: Methods for `spawn_agents`, `evaluate_forum`.


3. **Simulation Engine:**
* Build the `run_loop()` function. Use a global flag to Pause/Resume from UI.


4. **Web UI:**
* **/ (GET):** Dashboard. Form to set Topic, API Key. Start Button.
* **/posts (GET):** Returns HTML partial of the post feed (for HTMX polling).
* **/agents (GET):** Grid view of agent status.
* **/agent/{name} (GET):** Modal showing MD files.


5. **Polishing:**
* Ensure Markdown rendering in the frontend uses a library (like `markdown-it` via CDN).
* Add error handling if the LLM produces malformed JSON.

* `DEFAULT_AGENT_COUNT`: 10
* `MOTHER_LOOKBACK_K`: 25
